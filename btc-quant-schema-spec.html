1. 版本四元组 + run_id（吸收 GPT：Feature Versioning）

run_id      = "<YYYY-MM-DD>.<当日第N次compute>"     例: "2026-09-08.2"  ← 重算即新 run_id,绝不静默覆盖
versions    = {
  strategy_hash : sha256(config/strategy.yaml)[:12]   # 自动,内容即版本,替代手工 v0.3 头
  engine        : "v1.0"       # compute.py 自身版本
  feature       : "fv002"      # 特征口径变更才 bump(例: E2 启用 9/7 = fv001→fv002)
  prompt        : "p001"       # LLM 提示词版本
}
规则:
- snapshot / history 行 / ledger 行 / 日报页脚 全部携带 run_id + versions
- verify_report 校验: 日报 ⑧ 引用的 snapshot run_id == 当日最新 run_id,否则 FAIL
- 特征口径迁移(如 OI_change_24h→72h) = feature bump + 05_决策记录,旧 run 行永不改写

这解决 9/7 E2 回填暴露的问题：当时快照被 11:29 批次覆盖且无标记，事后无法区分"当日原算"与"回填重算"。

3.1 判读口径 ledger-r1（先定死再记账）

输出方向命中判据(ret=次日实际 24h 收益)统计归属
STRONG_LONG / LONGret > +0.5%方向准确率分母
STRONG_SHORT / SHORTret < −0.5%方向准确率分母
NEUTRAL|ret| ≤ 0.75%单独"横盘命中率"，不进方向分母（横盘类不再稀释）
NO_EDGE不计命中（合规输出，不算失败）单独记 NO_EDGE 频率与后续 ret 分布
range_hit：close ∈ [range.low, range.high]（全部方向均计）；MAE=|close−区间中值|；MFE=窗口内最大有利偏移（评估区间质量）

样本纪律：≤14 天不展示命中率；14~30 天标注"样本不足"；基线对比（Always Neutral / Momentum / Engine）同日输出。

4. strategy.yaml signals 声明式设计（吸收 GPT：Signal Registry）

# 追加段(与现有 weights/thresholds/windows 并存,compute 遍历本段自动打分)
signals:
  - id: A1_pct_1h      dim: A   scorer: score_pct_change   params: {scale: 1.0}
    semantics: momentum         direction_rule: none        # 动量: 数值即方向
    window: rolling_1h          threshold_ref: null
  - id: A6_rsi14       dim: A   scorer: score_rsi           params: {}
    semantics: mean_reversion    direction_rule: overbought_is_bearish   # 超买=负分
    window: rolling_14d         threshold_ref: A6_rsi
  - id: E1_funding     dim: E   scorer: score_funding       params: {}
    semantics: positioning       direction_rule: extreme_positive_is_bearish  # 正极端=拥挤反向
    window: rolling_now          threshold_ref: E1_funding_rate
  - id: E2_oi_change   dim: E   scorer: score_e2_oi         params: {score_per_pct: 4.0, score_cap: 40.0}
    semantics: leverage          direction_rule: aligned_with_price   # 价OI同向为正
    window: daily_oi_series      threshold_ref: E2_score
    guard: {same_source_required: true}                     # ← 缺陷#1 修法入口
  - id: B2_vol_ratio   dim: B   scorer: score_volume_ratio  params: {}
    semantics: participation     direction_rule: expansion_bullish
    window: rolling_24h          threshold_ref: B2_volume_ratio
engine:
  main_signal_from: [A, B, E]
  composite_legacy: true        # v1 兼容输出;v2 研究路径走 dim_scores/regime
R2 待拍板：signals 声明入 strategy.yaml（SSOT 内演进，推荐）还是独立 signal_registry.yaml？——请二选一。

声明式收益：新信号=加一段 YAML，不碰 compute 核心（回应"compute 变泥球"担忧的结构性手段）；direction_rule + guard 字段让"方向语义"与"同源守卫"成为一等公民（缺陷 #1 的 E2 只需声明 same_source_required: true）。
