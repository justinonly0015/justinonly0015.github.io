1. 核心结论（先读这段）

① ChatGPT 评审 #1 与 v2.1 红队收敛后的方向正确：永续升为独立数据层 + 合约状态机 + 预测账本 + 防泄漏/防重复计权，且当前阶段（仅 7 天数据）不应增加指标、不应上概率/ML。
② 但评审基于"只看网页"，仓库里已存在它列为 P0 的预测回看工具（review_history.py，L4 已实现）。
③ 真正的拦路问题它没看到：E 维(合约) 9/5~9/7 连续三天打分空窗——主源 binance_fapi 不可达时降级链未兜住；以及多所数据源(OKX/Bybit/Deribit)在主执行机上全部未实测可达性。
④ v2 第一刀不是写状态机，而是数据可靠性 + 数据源实测。

2. ChatGPT 评审 #1 的核验结果（已实现 vs 真缺口）

2.1 它说对的（仓库实证）

它的判断仓库实证
"7维34指标实际只跑 A/B/E"属实。compute.py：composite = A/B/E 归一加权 20:10:25；dim_scores 中 C/D=None；F 仅 F6 单点背景。9/8 实际非空打分仅 10 个：A1/A2/A3/A5/A6 + B2/B3 + E1/E2/E3
"横盘太宽泛，-6 与 -28 同档"属实。direction_threshold=±30 单阈值，|composite|≤30 全部"横盘"；9/2 BTC -28.2 判横盘实际 +1.26%，9/3 判横盘实际 +4.17%（后者即事件驱动行情）
"引擎权威、LLM 只解读" 架构好已是铁律：strategy.yaml SSOT + verify_report 快照守卫 + "缺失禁止虚构" 口径
"缺宏观 F；事件日 A/B 滞后"属实：yahoo/fred 未启用，F 维仅 alternative.me 的 F6
"权重是人为经验"成立，但它自己也承认需 30~60 天数据后再学习——当前阶段不动

2.2 它没看到的（仓库已领先）

它的 P0 建议仓库现状
"预测复盘是最大产品缺口"已有雏形 scripts/review_history.py（L4，2026/09/07 定稿）：逐日 方向 vs 次日实际收益。但仅 CLI，未进日报/首页，判读口径粗（±1% 内算"横盘带内"），方向类判断样本仅 1 次（全押横盘）
"方向分级 7 档"半成品 snapshot 已存 strength=|composite|/threshold 字段，但日报未使用——扩档只是展示层改动
数据积累节奏 0-14/30-90/90+ 天预设一致 strategy.yaml failure_detection 已含 ic_rolling_days:90 / accuracy_min_pct:50

3.1 新发现的硬问题：E 维三天打分空窗

日期derivatives 源E1/E2/E3/E4/E5 快照分
9/5 ~ 9/7（9/5 日报自称"降级至 gate.io"）全部 None —— 引擎连续 3 天没吃到合约分
9/8binance_fapi（补采文件落盘）E1=0 / E2=-40(BTC OI 降~10%) / E3 正常

含义：主源不可达的日子，降级链路没有真正兜住 E 维打分；而日报中的 E 数字（如 GPT 引用的 9/7 "OI -2.6%"）与引擎快照对不上账，链路不可追溯。这是 v2"数据可靠性"要解决的第一个现实案例。

4. ChatGPT 评审 #2（v2 → 红队 → v2.1）的核验

4.1 该保留的（与仓库实况一致）

v2.1 主张核验
永续从"一个维度"升为独立数据层（Spot/Perpetual/Macro/On-chain）对。E 维在权重表里是 25 的"皇冠"，但打分只有 3 个指标且读数不稳（见 3.1），确实配不上"核心桥梁"地位
合约不输出总分，输出状态机（Long build-up / Short covering / Liquidation flush / Crowded long…）+ evidence + confidence对。直接替代现"LLM 看图说话"的 regime 描述，且可防"OI↓+价↑ 就称 short-covering"的伪因果（它红队自己也指出）
防重复计权：OI/Funding/LS/Basis/CVD 高度相关，同组不重复加权对。打中 20:10:25 手工加权的要害；也支持"打分指标数不增加"的纪律
预测账本 + available_time 防 look-ahead + 基准模型 + 删指标实验对。仓库已有 timeline 语义（T=UTC 00:00，日级源 T-1 完整日）基础，账本升级是自然延伸
现阶段（7 天数据）禁止：概率/校准/ML/权重学习对。与仓库 failure_detection 的 90 天回测预设一致

4.2 该打折的（未结合仓库落地约束）

v2.1 设想落地约束
多所聚合 Binance/OKX/Bybit/Deribit主执行机（北京网络）连 fapi.binance.com 都不通（仅 vision 通、gate 间歇通）——OKX/Bybit/Deribit 可达性全部未实测。v2 数据宇宙边界由实测结果决定，不由设计决定
Options IV/Skew、ETF Flow、MVRV/SOPR、稳定币供应多数无免费源或需付费 key（glassnode/coinalyze 高级字段等）→ 明确延后
4H/24H/7D 多周期层会成倍放大日报/验证复杂度；仓库存储粒度（每日一行 history）暂不支持——列为远期
"删除 composite"红队自己也改为"保留做 UI"。仓库 v0.3 SSOT 结构支持演进：composite 降级为展示 + 方向粗分，信号层后续输出 factor vector

5. v2 落地方案（映射到本仓库文件）

层改动文件
数据层derivatives schema 升级：每所原始读数分开存（binance/gate 各自 funding/OI/LS/liq），聚合层另算，不做简单加总；funding 拉 7d 历史算 funding percentile；klines 的 taker buy 量落库（现货主动买卖倾向，免费）；现货价-永续 mark 价差 = basis（无需季度合约）fetch_binance_e.py / collect.py / compute.py / strategy.yaml
爆仓常驻binance 主源日也从 gate 单独拉爆仓聚合（混合源），或申请 coinalyze 免费 key 一源解决 E4/E5 + 跨所 OIcollect.py / strategy.yaml sources
状态机新增 regime.py：OI 方向 × 价格方向 × funding × 爆仓 × taker → 输出 regime 标签 + evidence + confidence；LLM 只解读不发明新增 scripts/regime.py
预测账本data/ledger/forecast_*.json：方向/区间/驱动/失效条件；次日回填 actual(high/low/close) 与 result(direction_hit/range_hit/MAE)；review_history 升级为命中率+区间命中率新增 data/ledger/ + review_history.py v2
护栏打分指标数不增加（保持 ~10 常驻）；相关性分组防重复计权；数据缺失超阈值 → 输出 NO EDGE（不做强制预测）strategy.yaml / compute.py
文档新规格文档把字段/口径/状态机规则定死，决策记入 05_决策与口径记录新增 07_Research_Engine_v2_规格.md

5.1 明确不做（与 v2.1 红队结论一致）

期权层、ETF flow、链上 MVRV/SOPR、7D 预测层、概率校准、权重学习、ML——全部等：① 数据源可达性实测；② 30~60 天历史积累。

6. 执行顺序

Phase 0 — v2 规格书入库（07_*.md，半天）：定死字段/口径/状态机规则/账本 schema
Phase 1 — 数据层：先做可达性实测（okx / bybit / deribit / coinalyze / gate 爆仓各探一个公开端点），实测决定源清单；再 schema 升级 + 爆仓常驻 + funding 分位 + taker 落库
Phase 2 — scripts/regime.py 合约状态机，替代 LLM 看图说话
Phase 3 — 预测账本闭环：昨日预测 → 今日验证 → 命中率/区间命中率进日报与首页
Phase 4+（30 天以后） — 基准模型对比（Always Neutral / Momentum only / 前 24h 方向）、删指标实验、权重学习

7. 一句话总结

v2 的正确路线 = ChatGPT v2.1 红队收敛后的框架（永续独立数据层 + 状态机 + 预测账本 + 护栏），但第一步不是写状态机，而是把数据地基打牢：解决 E 维空窗与降级兜底、实测多所可达性、让爆仓常驻。网页只是观察窗口，仓库里的流水线才是研究对象本身。
