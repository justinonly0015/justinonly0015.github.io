撤回：v2.1 稿及此前分析声称"9/5~9/7 E 维打分连续三天空窗、日报出现引擎不存在的数字、存在第二条数据链"。经复核（首次核验误用长键名 E1_funding_8h_pct，快照实际存短键 E1/E2/E3），该结论不成立。正确事实：
• 9/5~9/7 引擎 E 分齐全：9/6 E2 = BTC -6.1 / ETH +37.3；9/7 E2 = BTC -10.3 / ETH -31.3（E 维 -3.43 / -10.43）
• composite 与日报完全对账：9/6 BTC -10.3 / ETH -2.0；9/7 BTC -6.1 / ETH -4.9 —— 日报中 OI -2.6%/-7.8% 等数字均可回溯到快照
• 05_决策记录 L1：E2 打分 9/7 启用后按纪律回填 9/5~9/7 并重算（9/6 BTC -9.4→-10.3、9/7 -4.6→-6.1），快照/history/日报 ⑧ 同步更新且 verify PASS
教训：审计结论必须先对键名/口径做单元级确认，再做跨层对账。本勘误即"可验证"原则的第一次实战。

4. 冻结总原则（v2.2）

① 任何进入研究结论的数据必须可追溯、可复现、可验证（report → run_id → feature → raw_record）
② 原始证据按留存策略落盘归档，禁止重算覆盖不可逆（保留 run_id 区分原算/重算）
③ 主信号只走 Factor Vector，composite 仅为 UI legacy
④ 引擎输出域 = 方向 6 态含 NO EDGE；regime 只给 evidence+rule_match，不给伪概率
⑤ 预测必须记账：Ledger 先于一切模型工作
P0-A Data Integrity ≡ P0-B Prediction Ledger ≡ P0-C Perpetual Core（OI/Funding/Liquidation/Taker/Perp Premium）→ P1 Regime → P2 Forecast(≥30d) → P3 统计(60~90d) → P4 ML(最后)

6. P0-A：Data Integrity v2.2

项规则
raw 归档data/raw/<date> 全量保留 ≥90 天（落实 retention）；补采集覆盖前先备份旧文件为 derivatives.{run_id}.json

7. P0-B：Prediction Ledger（排期先于 regime）

{"run_id","date","coin","direction":"STRONG_LONG|LONG|NEUTRAL|SHORT|STRONG_SHORT|NO_EDGE",
"range_low","range_high","drivers":[],"regime":"..","rule_match":0.8,"data_quality":"medium",
"invalidation":"..",
"actual":{"high","low","close","ret_24h_pct","mfe_pct"},"result":{"direction_hit","range_hit","mae","mfe"}}

判读口径：方向准确率分母仅计 非 NEUTRAL 预测；NEUTRAL 单独统计（|ret|≤0.75% 为命中）；区间命中 = close∈[range_low,range_high]；MAE 对区间中值；MFE = 窗口内最大有利偏移（评估情景质量）。≤14 天不出命中率，14~30 天标注样本不足。

8. P1：Regime v1 — 输出 JSON 定死（无伪概率）

{"regime":"SHORT_COVERING","evidence":["price_up","oi_down","funding_negative","liq_short"],
"rule_match":0.8,"data_quality":"medium"}
RegimePriceOIFundingLiquidationTaker
LONG_BUILD_UP↑↑↑/正—买↑
SHORT_BUILD_UP↓↑↓/负—卖↑
SHORT_COVERING↑↓中性/↓空爆↑—
LONG_LIQUIDATION↓↓↓多爆↑—
LEVERAGE_FLUSH剧震↓↓—↑↑量↑↑
NEUTRAL其余（含缺数据无法判定）

rule_match = 命中规则数/可用规则数（字段缺失则该规则不参与分母，如 E 源缺失日自动退化为 Price×OI 二维并如实标注）；data_quality 来自当日 coverage。
