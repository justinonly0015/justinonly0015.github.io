1. 冻结总原则（v2.1 第一原则）

任何研究结论，必须能沿"数据源 → 原始数据 → 标准化数据 → 指标 → 信号 → 日报"完整追溯。任一环断裂，该数据不得作为研究结论使用。日报里的每个数字都应能追到 交易所 → 字段 → API → 时间戳。这一条比增加任何指标都重要。
P0-A Data Integrity（数据完整性）≡ P0-B Prediction Ledger（预测账本）≡ P0-C Perpetual Core（永续核心：OI/Funding/Liquidation/Taker/Perp Premium）
P1 Regime（5~6 态，只出 evidence）→ P2 Forecast（≥30 天数据）→ P3 统计模型（60~90 天）→ P4 ML（最后一层，非卖点）

5. P0-A：Data Integrity — 字段与门禁定死

5.1 derivatives schema v2（每所原始读数独立存）

{"date":"2026-09-08","coin":"BTC",
"fields":[{"name":"oi_usd","value":1.23e10,"exchange":"binance","scope":"binance_only","ts":"..."},
{"name":"liq_24h_usd","value":1.84e8,"exchange":"gate","scope":"gate_only","ts":"..."}]}

要点：原始数据永远保存（不覆盖）；聚合层另算并标注 scope；每字段带 exchange/scope/ts。任何"看起来像全市场"的输出必须能下钻到单所。

5.2 Data Quality Gate（每字段）

属性规则
freshness超过字段级阈值（如 OI ≤30min、日级源 T-1 完整日）→ 标 stale，不进打分
fallback 记录主源→备源切换必须落日志：哪一刻、为何、用了哪个 scope
可追溯链日报数字 → snapshot → reading → raw 文件 → API response + 时间戳；链断即弃用
E 维空窗防护主源不可达且备源无数据时：E 维输出 NO DATA（而非 0 或静默），日报与引擎强制一致

6. P0-B：Prediction Ledger — schema 与判读口径定死

6.1 记录结构（每日每币）

{"date","coin","direction":"涨|横盘|跌","range_low","range_high","composite","dim_scores",
"drivers":[..],"regime":"..","rule_support":"3/4",
// 次日回填
"actual":{"close","high","low","ret_24h_pct"},"result":{"direction_hit","range_hit","mae"}}

6.2 判读口径（Ledger 化第一步，先定死再记账）

判项口径
方向准确率分母仅非横盘预测（涨/跌）计入；横盘预测不占方向准确率分母（解决"横盘承担太多"）
横盘预测单独统计横盘命中 = |ret_24h| ≤ 0.75%；超带记失准幅度，单独累计"横盘失准率"
区间命中actual close ∈ [range_low, range_high]
误差MAE = |actual close − 区间中值|

样本纪律：≤14 天不出任何命中率数字；14~30 天可显示但标注"样本不足"。

11. 一句话总结

v2.1 = 先把 10~12 个核心变量跑稳定、把每一个数字的来路钉死、把每一天的预测记账并对账，然后连续积累 30→60→90 天，最后让数据自己决定留下什么。目标不是"预测 BTC 涨跌"，而是"建立一个能证明自己预测能力的研究系统"。
